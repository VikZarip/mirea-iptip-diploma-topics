# Разработка веб-сервиса автоматического построения диаграмм архитектуры (модель C4) по исходному коду и конфигурации репозитория

**Статус:** Свободно

**Уровень:** бакалавриат

## Краткое описание

Архитектурные диаграммы в проектах рисуют вручную, и они быстро перестают соответствовать коду. Тема посвящена разработке веб-сервиса, который анализирует репозиторий (docker-compose, манифесты Kubernetes, файлы зависимостей, структуру модулей) и автоматически строит диаграммы в нотации C4 — контекста, контейнеров и компонентов — с возможностью ручной правки и экспорта.

## Ожидаемый результат

- Веб-сервис, принимающий ссылку на Git-репозиторий или архив проекта.
- Внутренняя модель архитектуры (системы, контейнеры, компоненты, связи).
- Генерация диаграмм C4 уровней Context / Container / Component.
- Экспорт в Structurizr DSL, PlantUML (C4-PlantUML), Mermaid, PNG/SVG.
- Пояснительная записка, руководство пользователя, презентация.

## Возможные функции/компоненты

- **Загрузка проекта**: клонирование публичного репозитория по ссылке или загрузка архива.
- **Анализаторы**: docker-compose.yml, Kubernetes-манифесты, package.json / requirements.txt / pom.xml, структура пакетов и импорты.
- **Сопоставление с C4**: сервисы → контейнеры, БД/брокеры → внешние контейнеры, модули → компоненты, сетевые зависимости → связи.
- **Редактор**: ручное переименование, скрытие и добавление элементов поверх автоматически построенной модели.
- **Экспорт**: Structurizr DSL, C4-PlantUML, Mermaid, изображения.
- *Опционально*: сравнение двух версий репозитория (что изменилось в архитектуре), запуск в CI.

## Технологические ожидания

- Backend: Python (FastAPI) или Node.js/TypeScript; парсинг YAML/JSON, анализ импортов (ast для Python, ts-morph для TS).
- Визуализация: Mermaid / PlantUML / Structurizr, на фронтенде React + библиотека графов.
- Развёртывание: Docker.

## Метрики успеха

- Поддержка не менее 2–3 типов конфигураций (docker-compose, Kubernetes, файлы зависимостей одного языка).
- На 5+ открытых репозиториях сервис находит не менее 80% контейнеров, выделенных экспертом вручную.
- Построение диаграммы для среднего репозитория — не дольше 1 минуты.

## Основные use cases

- **Разработчик** вставляет ссылку на репозиторий и получает диаграмму контейнеров для README.
- **Архитектор** правит автоматически построенную модель и экспортирует её в Structurizr DSL.
- **Новый участник команды** быстро разбирается в устройстве незнакомого проекта.

## Актуальность

- Модель C4 стала де-факто стандартом лёгкого документирования архитектуры; поддержание диаграмм в актуальном состоянии вручную трудоёмко.
- Для бакалаврской ВКР научная новизна не требуется: акцент на проектировании и реализации работающего сервиса.

1. Изучение модели C4 и инструментов (Structurizr, C4-PlantUML, Mermaid, аналоги автогенерации).
2. Выбор источников информации в репозитории и правил сопоставления с C4.
3. Проектирование архитектуры сервиса и внутренней модели.
4. Реализация анализаторов и генерации диаграмм.
5. Реализация редактора и экспорта.
6. Проверка на открытых репозиториях, сравнение с ручными диаграммами, оформление ВКР.
