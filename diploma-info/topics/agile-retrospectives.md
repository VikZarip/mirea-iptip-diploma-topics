# Разработка веб-приложения для проведения ретроспектив и сбора обратной связи в agile-командах

**Статус:** Свободно

**Уровень:** бакалавриат

## Краткое описание

Ретроспектива — ключевая практика agile-команд, но часто проходит формально: решения не записываются, их выполнение не отслеживается, а распределённым командам неудобно работать с обычными онлайн-досками. Тема посвящена разработке веб-приложения для проведения ретроспектив в реальном времени с готовыми форматами, анонимным голосованием и контролем выполнения принятых решений от спринта к спринту.

## Ожидаемый результат

- Веб-приложение для проведения ретроспектив в реальном времени.
- Библиотека шаблонов форматов ретроспектив.
- Модуль задач (action items) с отслеживанием выполнения между встречами.
- Аналитика по команде: настроение, повторяющиеся проблемы, выполнение решений.
- Пояснительная записка, руководство пользователя, презентация.

## Возможные функции/компоненты

- **Комнаты команд**: приглашение по ссылке, роли фасилитатора и участника.
- **Форматы**: Start-Stop-Continue, 4L, Mad-Sad-Glad, Sailboat; создание собственных шаблонов.
- **Этапы встречи**: сбор карточек (скрыто/открыто), группировка, анонимное голосование, обсуждение с таймером.
- **Action items**: ответственный, срок, перенос невыполненных задач на следующую ретроспективу.
- **Аналитика**: индекс настроения команды, облако повторяющихся тем, процент выполненных решений.
- *Опционально*: экспорт в Markdown/PDF, интеграция с Telegram для напоминаний.

## Технологические ожидания

- Backend: Node.js (NestJS) или Python (FastAPI) + WebSocket.
- Frontend: React/Vue.
- БД: PostgreSQL, Redis для состояния комнат.
- Развёртывание: Docker.

## Метрики успеха

- Одновременная работа не менее 15 участников в комнате без заметных задержек.
- Полный цикл ретроспективы (сбор → голосование → решения) проходит в одном приложении.
- Положительная оценка удобства по итогам апробации (опрос SUS ≥ 70).

## Основные use cases

- **Скрам-мастер** создаёт ретроспективу по шаблону и приглашает команду.
- **Участник** анонимно добавляет карточки и голосует за важные темы.
- **Команда** фиксирует решения с ответственными, а на следующей встрече видит, что выполнено.
- **Руководитель** смотрит динамику настроения и повторяющиеся проблемы нескольких спринтов.

## Актуальность

- Распределённые команды стали нормой; популярные сервисы ретроспектив платные или недоступны в РФ.
- Для бакалаврской ВКР научная новизна не требуется: акцент на проектировании и реализации работающего приложения.

## Методы, модели и данные

- Совместное редактирование в реальном времени (WebSocket, CRDT/оптимистичные обновления).
- Простая аналитика текстов карточек (частотный анализ, кластеризация по ключевым словам).
- Данные: результаты апробации в учебных проектных командах.

## Ключевые публикации

- Derby E., Larsen D., Horowitz D. *Agile Retrospectives, Second Edition: A Practical Guide for Catalyzing Team Learning and Improvement*. Pragmatic Bookshelf, 2024. [pragprog.com](https://pragprog.com/titles/dlret2/agile-retrospectives-second-edition/) — основной источник о методе: пятиэтапная структура ретроспективы, каталог активностей, проведение в распределённых и гибридных командах.
- Andriyani Y., Hoda R., Amor R. *Reflection in Agile Retrospectives*. XP 2017, LNBIP vol. 283, Springer, 2017. [doi:10.1007/978-3-319-57633-6_1](https://doi.org/10.1007/978-3-319-57633-6_1) — эмпирическое исследование (открытый доступ): сама встреча не гарантирует настоящей рефлексии; обосновывает модуль контроля выполнения решений.

## Практическая польза

- Ретроспективы становятся результативнее: решения не теряются, а команда видит прогресс между спринтами.

### Этапы проекта (план студента)

1. Изучение практик ретроспектив и аналогов (EasyRetro, Retrium, Parabol, Miro).
2. Формулирование требований, ролей и сценариев.
3. Проектирование архитектуры и механизма работы в реальном времени.
4. Реализация комнат, форматов, голосования и action items.
5. Реализация аналитики.
6. Апробация в учебной команде, оценка удобства, оформление ВКР.
