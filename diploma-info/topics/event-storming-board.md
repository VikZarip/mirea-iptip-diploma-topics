# Разработка веб-приложения для совместного моделирования предметной области методом Event Storming

**Статус:** Зарезервирована

**Уровень:** бакалавриат

## Краткое описание

Event Storming — метод совместного моделирования предметной области через доменные события, команды и агрегаты. В распределённых командах сессии проводят на универсальных онлайн-досках, которые не знают нотации метода: карточки не проверяются, а результат сложно превратить в артефакты проектирования. Тема посвящена разработке специализированной веб-доски для Event Storming с поддержкой нотации, совместной работой в реальном времени и экспортом модели.

## Ожидаемый результат

- Веб-приложение — интерактивная доска для сессий Event Storming.
- Поддержка нотации метода (типы карточек, цвета, допустимые связи).
- Совместное редактирование в реальном времени и история изменений.
- Экспорт результатов в JSON, PlantUML и Markdown.
- Пояснительная записка, руководство пользователя, презентация.

## Возможные функции/компоненты

- **Доска**: drag-and-drop карточек, масштабирование, временная шкала событий.
- **Нотация**: доменное событие, команда, актор, агрегат, политика, внешняя система, read model, проблемная зона; подсказки по допустимым последовательностям.
- **Этапы сессии**: Big Picture → Process Level → Design Level, режим фасилитатора.
- **Совместная работа**: курсоры участников, комментарии, история изменений.
- **Экспорт**: JSON-модель, PlantUML-диаграммы, Markdown-отчёт по агрегатам и событиям.
- *Опционально*: группировка карточек в ограниченные контексты (bounded contexts), подсказки формулировок событий.

## Технологические ожидания

- Frontend: React/Vue + Konva.js / React Flow.
- Backend: Node.js или Python (FastAPI) + WebSocket; синхронизация через Yjs (CRDT).
- БД: PostgreSQL.
- Развёртывание: Docker.

## Метрики успеха

- Одновременная работа 10+ участников на одной доске.
- Доска на 200+ карточек остаётся отзывчивой.
- Экспортированная модель корректно открывается в PlantUML.

## Основные use cases

- **Фасилитатор** создаёт сессию, приглашает экспертов и ведёт её по этапам.
- **Эксперт предметной области** добавляет доменные события на временную шкалу.
- **Архитектор** выделяет агрегаты и ограниченные контексты, экспортирует модель для проектирования.

## Актуальность

- Event Storming широко применяется при проектировании по DDD и микросервисной архитектуре; специализированных и доступных инструментов мало.
- Для бакалаврской ВКР научная новизна не требуется: акцент на проектировании и реализации работающего приложения.

## Методы, модели и данные

- Совместное редактирование на основе CRDT.
- Формализация нотации Event Storming как набора типов элементов и правил связей.
- Данные: учебные кейсы и примеры сессий из литературы.
