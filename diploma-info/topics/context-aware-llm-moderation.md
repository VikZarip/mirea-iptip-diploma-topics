# Разработка метода контекстно-зависимой модерации пользовательского контента в закрытых социальных сообществах с использованием больших языковых моделей

**Статус:** Зарезервирована

**Уровень:** магистратура

> Тема предложена студентом: [issue #32](https://github.com/VikZarip/mirea-iptip-diploma-topics/issues/32).

## Краткое описание

Модерация в закрытых сообществах зависит от их собственных правил и от контекста обсуждения. Анализ сообщения без контекста приводит к ошибочным блокировкам и пропущенным нарушениям, а добавление контекста целиком увеличивает затраты и не гарантирует улучшения качества.

Основная исследовательская задача — метод адаптивного отбора контекста для LLM-модерации: какие сообщения из истории обсуждения передавать модели, чтобы повысить качество решений без роста затрат. Метод встраивается в клиент-серверную социальную сеть с закрытыми сообществами.

## Ожидаемый результат

- Метод адаптивного формирования контекста, учитывающий историю обсуждения и правила сообщества.
- Экспериментальное сравнение метода с базовыми подходами по качеству классификации, времени обработки и вычислительным затратам, включая оценку вклада отдельных признаков отбора.
- Подсистема модерации на готовых LLM без дообучения, интегрированная в серверную часть.
- Клиент-серверный прототип социальной сети с закрытыми сообществами и Android-клиентом для демонстрации работы метода.
- Научная статья и пояснительная записка.

## Возможные функции/компоненты

- Модуль адаптивного формирования контекста на основе истории обсуждения.
- Подсистема модерации на локально развёрнутой LLM; индивидуальные правила модерации для каждого сообщества.
- Механизм принятия решений и передачи неоднозначных случаев администратору сообщества.
- Модуль экспериментальной оценки: метрики, сравнение подходов, абляция признаков.
- Серверная часть с REST API и PostgreSQL.
- Android-приложение (Jetpack Compose): авторизация, закрытые сообщества и участники, права администраторов, публикации, комментарии, лента — в объёме, достаточном для демонстрации метода.

## Технологические ожидания

- Android: Kotlin, Jetpack Compose, Coroutines, Flow, Retrofit, Dagger 2.
- Backend: Kotlin, Ktor или Spring Boot; REST API, JSON.
- База данных: PostgreSQL.
- LLM: локально развёрнутая открытая модель семейства Qwen, без дообучения.
- Эмбеддинги: BGE-M3 (мультиязычная, локально).
- Docker.

## Метрики успеха

- Macro-F1 (основная), Precision и Recall выявления нарушений.
- False Positive Rate — доля ошибочно заблокированных допустимых сообщений.
- Среднее количество токенов и время обработки одного сообщения с учётом отбора контекста.
- Сравнение с базовыми подходами и вклад каждого признака отбора (абляция).
- Доля спорных случаев, переданных на ручную модерацию; корректность основных сценариев прототипа.

## Основные use cases

1. Пользователь создаёт закрытое сообщество, приглашает участников и задаёт правила общения.
2. Участник публикует запись или комментарий — система анализирует их с помощью LLM с учётом правил сообщества и отобранного контекста обсуждения.
3. При вероятном нарушении система блокирует публикацию или передаёт спорный случай администратору.
4. Администратор разбирает спорные случаи и при необходимости меняет правила сообщества.

## Научная новизна и актуальность

Предыдущие исследования показали, что контекст может влиять на правильность оценки сообщений, однако его добавление не всегда улучшает качество модерации.

Новизна — метод адаптивного отбора контекста для LLM-модерации. В отличие от подходов с фиксированным числом предыдущих сообщений или одним родительским комментарием, метод выбирает наиболее полезные сообщения из истории обсуждения по признакам:

1. **Структура обсуждения** — на какое сообщение отвечает пользователь и что предшествовало ему в диалоге.
2. **Смысловая близость** к проверяемому комментарию (модель эмбеддингов BGE-M3).
3. **Связи между участниками** — кому адресован комментарий, упоминания и цитирование.
4. **Близость по времени** как дополнительный признак значимости.

Каждому сообщению присваивается оценка важности. Непосредственный контекст ответа сохраняется всегда, остальные сообщения отбираются с учётом повторов информации и ограничения на число токенов — состав и объём контекста зависят от конкретного обсуждения. Правила сообщества передаются модели полностью, чтобы исследование было сосредоточено на отборе контекста обсуждения.

**Гипотеза:** адаптивное формирование контекста повышает качество модерации при сопоставимых или меньших затратах на обработку сообщения.

## Методы, модели и данные

- Сравниваемые подходы (одинаковые правила сообщества и одна LLM семейства Qwen во всех случаях):
  1. без контекста обсуждения;
  2. с родительским комментарием (подход Kumar et al.);
  3. с фиксированным окном предыдущих сообщений;
  4. **предлагаемый:** адаптивный отбор по четырём признакам.
- Абляция: вклад каждого признака отбора в качество модерации.
- Данные — см. «Источники данных».
- Опционально: сравнение со специализированной моделью решений Jev (TypeSafe AI, ранний доступ с сентября 2026) через API.

## Ключевые публикации

- Pavlopoulos J. et al. *Toxicity Detection: Does Context Really Matter?* ACL, 2020. [ACL Anthology](https://aclanthology.org/2020.acl-main.396) — контекст меняет оценку человеком, но не улучшил исследованные классификаторы. Отличие работы: современные LLM и отбор контекста по смыслу и связям между сообщениями вместо простого добавления предыдущих комментариев.
- Kumar D., AbuHashem Y., Durumeric Z. *Watch Your Language: Investigating Content Moderation with Large Language Models*. ICWSM, 2024. [doi:10.1609/icwsm.v18i1.31358](https://doi.org/10.1609/icwsm.v18i1.31358) — LLM-модерация по правилам 95 сообществ Reddit; родительский комментарий исправляет 35% ошибок. Отличие: автоматический выбор значимых сообщений из всей истории обсуждения.
- Kolla M., Salunkhe S., Chandrasekharan E. et al. *LLM-Mod: Can Large Language Models Assist Content Moderation?* CHI EA, 2024. [doi:10.1145/3613905.3650828](https://doi.org/10.1145/3613905.3650828) — LLM-модерация обнаружила лишь 43,1% нарушений. Отличие: проверить, сокращает ли отбор релевантного контекста пропуски нарушений и ошибочные блокировки.
- Park C. Y. et al. *Detecting Community Sensitive Norm Violations in Online Conversations*. Findings of EMNLP, 2021. [doi:10.18653/v1/2021.findings-emnlp.288](https://doi.org/10.18653/v1/2021.findings-emnlp.288) — набор NormVio: ветки Reddit с правилами сообществ и решениями модераторов.
- Xenos A. et al. *Toxicity Detection can be Sensitive to the Conversational Context*. 2021. [arXiv:2111.10223](https://arxiv.org/abs/2111.10223) — набор CCC: комментарии, размеченные с родительским сообщением и без него.

## Практическая польза

- Снижение нагрузки на администраторов сообществ за счёт автоматической обработки типовых нарушений.
- Меньше ошибочных блокировок благодаря учёту контекста обсуждения и правил конкретного сообщества.
- Применимость метода в социальных сетях, корпоративных коммуникационных системах и образовательных платформах.

### Источники данных

- **Основной набор — NormVio** ([github.com/chan0park/NormVio](https://github.com/chan0park/NormVio)): ветки Reddit с правилами сообществ и решениями модераторов. Распространяется без текстов (только ID сообщений), тексты восстанавливаются скриптом авторов — см. рекомендации ниже.
- **Русскоязычный набор** (300–500 примеров): перевод части основного набора отдельной LLM (не той, что модерирует) и минимальные пары — одно сообщение в сообществах с разными правилами и противоположным решением.
- **CCC** ([github.com/ipavlopoulos/context_toxicity](https://github.com/ipavlopoulos/context_toxicity)) — для проверки эффекта контекста.
- Контент прототипа социальной сети — только для демонстрации, не для оценки метода.

## Рекомендации куратора при одобрении

- **Проверить доступность NormVio до середины ноября 2026.** Набор выложен без текстов: их нужно восстановить через Reddit API и дамп PushShift (по оценке авторов — 20–30 часов), а тексты удалённых модераторами комментариев есть только в дампе, доступ к которому с 2023 года ограничен. С сентября 2026 в репозитории также висит предупреждение об ошибках в генерации немодерированных веток и сопоставлении правил. **Запасной вариант:** основным становится полусинтетический русскоязычный набор с правилами сообществ (6–10 сообществ с разными правилами, не меньше трети примеров — минимальные пары, генерирует одна модель, модерирует другая, выборку проверяют два человека, тестовые сообщества не участвуют в настройке метода), а CCC используется для проверки эффекта контекста. В CCC есть только родительское сообщение, поэтому признаки «участники» и «время» на нём не проверить.
- **Обязательный baseline — родительский комментарий** (подход Kumar et al.). Это ближайшее известное решение: без сравнения с ним нельзя показать, что адаптивный отбор лучше.
- **Jev — только опционально.** Модель в раннем доступе, независимых оценок её качества нет.
