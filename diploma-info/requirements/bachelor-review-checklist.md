# Чек-лист рецензирования ВКР бакалавра — 2026/27

Для руководителя (проверка версий) и студента (самопроверка перед сдачей). Основа — [bachelor-2026-27.md](bachelor-2026-27.md); принятые решения руководителя: 3 главы, 40–60 стр. Приоритеты замечаний: **К** — критично (недопуск/возврат), **Ж** — желательно, **М** — мелочь.

## 0. Общие параметры

- [ ] **К** Объём основного текста 40–60 стр. без приложений; приложения ≤ 1/3 объёма, ≤ 20 шт.
- [ ] **К** Все обязательные элементы на месте и в порядке: титул, задание, аннотация, оглавление, введение, главы 1–3, заключение, список источников, приложения
- [ ] **К** Оригинальность ≥ 55 % (Руконтекст) по тексту от введения до заключения
- [ ] **Ж** Один файл .docx по шаблону кафедры; нет заголовков третьего уровня
- [ ] **Ж** Тема на титуле, в задании и в тексте совпадает дословно с приказом

## 1. Аннотация

- [ ] **К** ≤ 150 слов; объект и предмет, цель, основные результаты, область применения
- [ ] **К** 5–7 ключевых слов, конкретных (не «система», «технология»), без точки в конце
- [ ] **Ж** В конце — объём основного текста и приложений (практика руководителя)

## 2. Введение (2–3 стр.)

- [ ] **К** Актуальность выведена из конкретной ситуации / потребности / ограничений существующих решений, а не из общих слов
- [ ] **К** Объект (класс систем / процесс) и предмет (конкретный аспект объекта) сформулированы; предмет у́же объекта
- [ ] **К** Цель одна, через улучшение характеристики: «Повышение/сокращение … посредством разработки …»
- [ ] **К** Задачи — 5 типовых (проблематика и постановка; анализ и требования; проектирование и стек; реализация, тестирование, оценка; выводы), соответствуют главам
- [ ] **Ж** Практическая значимость: кто, как и где использует результат
- [ ] **Ж** Структура работы: 1–2 предложения на главу
- [ ] **М** Нет научной новизны и гипотез как обязательных элементов (для бакалавра не требуются)
- [ ] Для ВКРС: общая цель/задачи проекта + индивидуальные цель/задачи участника

## 3. Глава 1. Анализ предметной области и постановка задачи (8–10 стр.)

### 1.1 Предметная область и бизнес-процессы
- [ ] **К** Описана сфера, участники, ключевые процессы и их связи — понятно постороннему читателю
- [ ] **К** Процесс «как есть» описан фактически: роли, последовательность операций, данные между участниками
- [ ] **К** Есть **диаграмма AS-IS** (BPMN / IDEF0 / UML / flowchart), читаемая, с пояснением в тексте
- [ ] **К** Сформулированы проблемы и ограничения текущего состояния (время, ошибки, ручные операции, бюджет)

### 1.2 Обзор и сравнительный анализ существующих решений
- [ ] **К** Рассмотрено ≥ 3–4 аналогов (коммерческие, open-source, нецифровые способы)
- [ ] **К** Критерии сравнения объективные и измеримые: функциональные + нефункциональные (производительность, стоимость, масштабируемость, документация…)
- [ ] **К** Есть **сравнительная таблица** решений × критериев
- [ ] **Ж** Выводы: что взять у аналогов, почему они неприменимы, какой пробел закрывает разработка

### 1.3 Формирование требований
- [ ] **К** Функциональные и нефункциональные требования разделены и представлены **таблицей** (пригодны для проверки в главе 3)
- [ ] **К** Постановка задачи — краткое ТЗ: что создаётся, для кого, ключевые характеристики
- [ ] **К** Выводы по главе — жирным абзацем в конце 1.3 (1–2 абзаца), без отдельного подраздела
- [ ] Для ВКРС: целевая аудитория, конкуренты, УТП, гипотезы рынка; бизнес-модель и go-to-market; экономическое обоснование

## 4. Глава 2. Проектирование системы (15–18 стр.)

### 2.1 Концепция и архитектура
- [ ] **К** Описано, как будет работать система после внедрения: процессы, участники, движение данных
- [ ] **К** Есть **диаграмма TO-BE**
- [ ] **К** Архитектурный стиль назван и обоснован относительно задачи, масштаба и требований главы 1
- [ ] **К** Есть **схема архитектуры**: компоненты и связи

### 2.2 Модель данных и интерфейсы
- [ ] **К** Ключевые пользовательские сценарии: шаги, действия, реакция системы; покрывают требования
- [ ] **К** Сущности, атрибуты, связи; есть **ER-диаграмма** (или иная наглядная модель данных)
- [ ] **К** **Макеты/прототипы ключевых экранов** с пояснениями, привязаны к сценариям
- [ ] **Ж** Интерфейсы между модулями / API: эндпоинты, форматы запросов и ответов, примеры

### 2.3 Технологический стек
- [ ] **К** Перечислены технологии для всех компонентов: фронтенд, бэкенд, СУБД, тестирование, деплой/CI
- [ ] **К** Для каждого — обоснование по объективным критериям (актуальность, зрелость, сообщество, совместимость, стоимость), а не «потому что знаю»
- [ ] **К** Выводы по главе — жирным в конце 2.3
- [ ] Для ВКРС: связь архитектуры с бизнес-целями и масштабированием; стоимость разработки и доступность специалистов

## 5. Глава 3. Реализация и тестирование (15–18 стр.)

### 3.1 Реализация
- [ ] **К** Структура репозитория, ключевые модули и их назначение; логика решения, а не перечень файлов
- [ ] **К** Архитектурные решения главы 2 реализованы (или отклонения объяснены)
- [ ] **Ж** Листинги — только ключевые/нетиповые фрагменты, с пояснениями, ≤ 10–15 % главы; полный код — в приложениях

### 3.2 Тестирование и развёртывание
- [ ] **К** Названы виды тестирования (модульное / интеграционное / системное / приёмочное), среда, инструменты
- [ ] **К** **Таблица тест-сценариев**: что проверялось, входные данные, ожидаемый и фактический результат — минимум happy path по каждому требованию
- [ ] **К** **Скриншоты** работы системы по ключевым функциям
- [ ] **Ж** Описано развёртывание: платформа, среда, шаги

### 3.3 Анализ результатов
- [ ] **К** Сопоставление с требованиями главы 1: что выполнено, что нет
- [ ] **К** **Таблица метрик «до/после»** — измеримые показатели (время операций, число ручных шагов, ошибки, производительность)
- [ ] **К** **Диаграмма** изменения метрик
- [ ] **К** Явный вывод о достижении цели из введения
- [ ] **К** Выводы по главе — жирным в конце 3.3
- [ ] Для ВКРС: MVP и его функции; готовность к рынку; экономические показатели

## 6. Заключение (1–2 стр.)

- [ ] **К** По каждой задаче введения — 1–2 предложения с результатом
- [ ] **К** Вывод о достижении цели (цель процитирована)
- [ ] **Ж** Практическая значимость и перспективы развития
- [ ] **К** Нет новой информации, не упомянутой в главах

## 7. Список источников

- [ ] **К** ≥ 20 источников; ≥ 50 % не старше 5 лет (кроме ГОСТов, нормативов, патентов)
- [ ] **Ж** Существенная доля зарубежных источников (практика руководителя)
- [ ] **К** Порядок — по первому упоминанию; на каждый источник есть ссылка в тексте [N] / [N, с. X]
- [ ] **К** Оформление по ГОСТ Р 7.0.5-2008 / ГОСТ 7.1-2003
- [ ] **Ж** Преобладают рецензируемые издания и официальная документация, а не блоги и форумы

## 8. Приложения

- [ ] **Ж** Только справочное: расширенные тесты, инструкция по установке, примеры данных, код
- [ ] **К** Обозначения буквами А, Б, В… (без Ё, З, Й, О, Ч, Ь, Ы, Ъ); сквозная нумерация страниц продолжается
- [ ] **К** На каждое приложение есть ссылка в тексте

## 9. Оформление (нормоконтроль)

- [ ] **К** А4, поля 30/15/20/20 мм, Times New Roman 14, интервал 1.5, отступ 1.25 см, по ширине
- [ ] **К** Нумерация страниц снизу по центру, сквозная; титул без номера
- [ ] **К** Заголовки глав и структурных элементов — прописными, с новой страницы, по центру, полужирно, «ГЛАВА 1 …»; параграфы «1.1 …»
- [ ] **К** Рисунки: подпись под рисунком «Рисунок 2.1 – Название», курсив; таблицы: «Таблица 2.1 – Название» над таблицей; нумерация в пределах главы; ссылки в тексте на каждый рисунок и таблицу
- [ ] **К** Раздел не начинается и не заканчивается рисунком
- [ ] **Ж** Оглавление автоматическое, заголовки совпадают с текстом
- [ ] **Ж** Листинги моноширинным, с названием сверху; формулы пронумерованы по главам
- [ ] **М** Нет опечаток, слипшегося текста, пустых страниц, разных шрифтов

## 10. Этика

- [ ] **К** Нет прямых заимствований без ссылок (в т.ч. из чужих ВКР)
- [ ] **К** Данные не сфальсифицированы: источник исходных данных указан, метрики воспроизводимы
- [ ] **К** Ссылки ведут на источники, действительно содержащие цитируемое

## 11. Презентация и доклад (перед защитой)

- [ ] **К** 12–16 слайдов по шаблону кафедры: тема; актуальность; объект/предмет/цель/задачи; AS-IS; таблица аналогов; требования; TO-BE и архитектура; ER; макеты; реализация; таблица тестов; метрики «до/после»; выводы
- [ ] **К** Доклад укладывается в 5 минут (репетиция с таймером)
- [ ] **Ж** Для предзащиты (11-я неделя): 3–5 минут, без демо кода — тема, задачи, степень выполнения, решения, текущие результаты

## Как пользоваться при рецензировании

1. Пройти чек-лист сверху вниз, отмечая невыполненное с приоритетом.
2. В рецензии разнести замечания на содержательные (разделы 2–6, 10) и формальные (0, 1, 7–9).
3. Каждое замечание: в чём проблема — где (раздел, страница, цитата) — почему — приоритет.
4. Замечания «К» блокируют переход к следующему этапу (предзащита / сдача в СДО).
